# 新谱处理与适配范围

## 结构检查

先运行 `score_transpose.py inspect`，再看原 PDF 渲染。检查输出页数、字体、图像数、文字和路径清单；这些信息不能自动判定源乐器。复杂表单、嵌套 XObject、非水平矩阵、CID 字体或扫描件可能需要其他解析器。

参考适配器中的路径 ID、字节码、调号分段、附点豁免、连线匹配和排版距离来自对应原文件。`known-scores.json` 以 SHA-256 限定其输入；改名不会影响匹配，内容变化则必须重新检查。不要删掉哈希检查来强行转换新谱。

## 音乐字体矢量谱

读取每页字体的 Encoding/Differences、Widths、FontMatrix 和必要的 ToUnicode，不以字体资源名或字节值猜音符。识别五线谱、谱号、音头、符干/符梁、附点、休止、调号/临时记号、延音、装饰音。记录每个音的页、系统、小节、声部、八度、时值和实际半音值。

`score_pdf.py` 参考解析器适合已测试的单行高音谱 LilyPond/Emmentaler PDF，未覆盖任意谱号、多谱表、复杂文本矩阵或所有 PDF 运算符。断言失败时，在工作目录检查原因并适配，不跳过断言。`nabucco1_adapter.py` 含页内延音状态的实现示例；新谱仍需检查跨系统延音。

## 轮廓矢量谱

`vector_paths.py` 按绘制操作提取路径、边界及平移归一化签名。分组能发现重复音头，但必须与原页对照：小圆点可能是附点、反复点、延长记号点或文本；细矩形可能是符干、小节线、加线或休止。

`wanquan_adapter.py` 是 1 页、7 系统、双声部合谱的验证实例，200 个音头中包括 1 个装饰音。它保留曲线、休止、文字和原分行；拆分 Tm/Td 保证共享文本段里的 a2 与左侧编号各回到正确位置。该谱没有音符上的独立临时变音，只在第 49 小节换调，其音高检查不能直接用于有临时变音的新谱。

对新轮廓谱逐个分类全部绘制对象，列出未知对象，再决定移动/保留/替换；未知对象未处理前不要输出“已全部核对”。保存原图形拓扑，变更坐标。新增调号使用真实音乐字形。检查白色遮挡路径、裁切路径、曲线分段和组合字符，不要删除看似重复的对象。

## 扫描件、混合格式、其他移调

扫描件需要 OMR 或手工录入 MusicXML/LilyPond。优先用已有本地识谱/制谱软件；不要将扫描图交给图像生成模型绘制乐谱。先识谱后逐小节核对，再移调。不能只改变调号或在图像上整体上下平移来代替识谱。

没有可用识谱工具时，对规模合理的谱可手工重建符号数据；若原图模糊，先完成可辨部分，再明确请求需要补充的具体位置。不要声称已安装了不存在的 OMR 能力。

锁定原有系统与分页：MusicXML 的 print/new-system、new-page，或制谱软件的显式换行/分页均可。休止 8 小节仍算 8 小节，原左侧数字原样保留；不要以重新生成的顺序号替代它们。复杂谱完整时值/事件检查须在符号表示中进行，路径数相同不能代替这一检查。

## 验证记录

保存源/目标哈希、所用移调、逐音对应、每页/每行事件数、原文字/编号比对及修正记录。程序检查和视觉检查分开记；从最终保存的文件读取音高/符号以验证真正写出的内容。

Bravura 字体取自 Steinberg 官方 Bravura 项目，位于 `assets/Bravura.otf`，随附 `Bravura-LICENSE.txt`（SIL Open Font License）。新增音乐符号可使用其 SMuFL 字形；优先保留原谱已有字形。
