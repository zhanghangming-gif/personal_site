# 乐谱索引与可定位核验

当前实现以 MusicXML 作为保留全部原始数据的基础，额外生成 JSON 索引。没有训练模型，
没有把模型自报的置信度当成正确率，也没有新增重新排版按钮。

## 已接入主流程

- `score_ir.py`：区分作品移调与乐器转换；按乐器偏移计算实际音高不变的记谱音程。
  音符、休止、和弦、装饰音、多声部时间轴使用精确分数；记录音名拼写、调号、拍号、
  谱号、歌词、标记、连线、来源摘要和位置。位置默认来自 XML 排版，不冒充原 PDF 坐标。
- `score_ir_audit.py`：逐小节比较音高拼写、起点、时值、声部归属、歌词、奏法、标记及
  连线终点。允许一致的声部重编号及和弦序列化顺序变化。差异保留事件 ID 和明确位置。
- `score_review.py`：保存原始识谱、结构修复后、转调后、排版导出的四份 IR，以及
  `score-review.json`。报告绑定输入 PDF、候选 PDF、XML 和 IR 摘要，并生成按小节分组的
  复核队列。仅在单谱表、印刷小节号、矢量小节线和识谱小节数量对应时附上原谱区域。
  区域对应不等于里面的音符已识别正确；多小节休止和不明确结构保留为未定位。
- 网页显示具体差异和期望/实际结果。原谱识别、转调数据、排版导出比较、输出 PDF
  独立识别分别报告。自动识谱分支缺少原谱和输出 PDF 的独立证据时保持 NEEDS_REVIEW，
  不再凭内部数据一致自动发放 PDF。三份已校对参考文件继续走原有摘要绑定的适配器。

## 尚未实现的范围

这不是全符号原生 PDF 编辑器。IR 是有范围的索引，原始 MusicXML 仍须保存；并非所有
MusicXML 扩展、字体样式、符梁排版或微分音均已核验。输出比较的数据由排版软件导出，
不是独立识别候选 PDF。已有 OMR 识错内容仍需要原 PDF 证据或人工校对。

局部 AI 识别器和受限补丁应用器尚未接到这条主流程，现阶段仅建立定位和证据队列。
已有 DeepSeek 自由脚本代理仍是独立实验，不因本次改动而上线。

下一步在小节区域中提取音头、谱线位置和变音记号的独立证据，校验后形成音符级映射；
只把无法消除的具体疑问交给视觉模型。补丁必须绑定源摘要、事件和依据，应用后重验。

## 验证

`python -m pytest tests -q`；新增测试覆盖精确时值、多声部、同音异名、漏音、歌词、
调号、跨符号连线、问题列表截断、原谱证据缺失以及小节区域映射条件。
